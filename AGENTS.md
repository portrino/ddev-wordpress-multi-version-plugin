# AGENTS.md

DDEV add-on (`ddev add-on get portrino/ddev-wordpress-multi-version-plugin`)
that runs one WordPress instance per version (`WP_VERSIONS`) in
`.Build/<label>` (`7.1` -> `71`), each on `<label>.<project>.ddev.site`, with
the plugin in the project root symlinked in. Modelled on
`konradmichalik/ddev-typo3-multi-version-extension`; keep commands and
conventions aligned with it where WordPress allows.

## Structure

- `install.yaml`: manifest. `post_install_actions` generate
  `config.wordpress-setup.yaml` (project type, docroot, hostnames) and
  one `commands/web/<label>` per version, because DDEV needs both before it
  starts. Generated commands carry the line
  `## Generated by the wordpress-multi-version-plugin add-on`, which
  regeneration and `removal_actions` look for.
- `docker-compose.wordpress-setup.yaml`: defaults (`WP_VERSIONS`,
  `WP_PLUGIN_SLUG`); projects override them in their own
  `docker-compose.zz-project.yaml`.
- `commands/web/install`, `commands/web/all`, `.setup/scripts/`
  (`utils.sh` helpers, `run` used by `ddev <label>` and `ddev all`).
- `apache/wordpress-versions.conf` + `.rules` (DDEV copies every file into
  `sites-enabled`, Apache only loads `*.conf`), `nginx_full/wordpress-versions.conf`.
  Both route by the numeric host label and replace WordPress' `.htaccess`.

The project type is `wordpress` (DDEV only ships WP-CLI for it) with
`disable_settings_management: true`; the instances get their own
`wp-config.php` from `ddev install`.

## Development

No build step. Test against a throwaway project:

```shell
mkdir wpmv-test && cd wpmv-test
printf '<?php\n/**\n * Plugin Name: Test\n */\n' > test.php
ddev config --project-name=wpmv-test --webserver-type=apache-fpm
ddev add-on get /path/to/this/checkout && ddev restart && ddev install all
```

Check both webserver types. Tests: `bats ./tests/test.bats` (tags `install`,
`release`), CI via `ddev/github-action-add-on-test`.

Everything with `#ddev-generated` ships to every project on its next
`ddev add-on get`.
