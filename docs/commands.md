# Commands

`<version>` is always `7.1` or the label `71`.

## `ddev install`

Installs or rebuilds instances, see [Installing instances](installation.md).

## `ddev <label> <command>`

Runs a command inside one instance (`.Build/<label>`), where a plain `wp` works:

```bash
ddev 71 wp plugin list
ddev 64 composer show
```

One command per version in `WP_VERSIONS` is generated by `ddev add-on get`.

## `ddev all <command>`

Runs a command in every installed instance, e.g. `ddev all wp cache flush`.

## `ddev open [<version>] [<path>]`

Opens the intro page, or an instance, in the browser (uses `ddev launch`):

```bash
ddev open              # intro page
ddev open 71 /wp-admin/
```

The intro page on the primary URL `https://<project>.ddev.site` lists every
version with its installed release, links, the admin login and the current
branch and commit.

It isn't called `launch` because DDEV removes a project command that shadows its
global `ddev launch`.

## `ddev worktree-init` / `ddev worktree-remove`

Set up and tear down a git worktree checkout, see [Git worktrees](git-worktrees.md).

## Quoting

DDEV custom commands don't keep quoting, so `ddev 71 wp eval '…'` breaks on
`$` or `;`. Use a file instead:

```bash
ddev exec "cd .Build/71 && wp eval-file file.php"
```

DDEV's own `ddev wp` points to `.Build`, where no WordPress lives. Use
`ddev <label> wp …` or `ddev all wp …`.
